## 1. Vocabulary You Will See

- **Repo:** short for repository. One project on GitHub. Like a folder that lives both on your computer and on GitHub at the same time.
- **Commit:** save a snapshot. Like Ctrl plus S, but git remembers every snapshot forever and lets you go back.
- **Push:** send your saved snapshots from your computer up to GitHub.
- **Pull:** grab the latest version from GitHub down to your computer.
- **Clone:** copy a GitHub repo down to your computer for the first time.
- **PAT:** Personal Access Token. The password GitHub gives you so git on your computer can push and pull without typing your real password every time.
- **API key:** a long secret password that lets your sync script log in to {TARGET_PLATFORM} automatically.
- **.env file:** a hidden file that holds your API key. It never gets committed to GitHub. Stays on your computer only.
- **YAML:** a simple file format for structured data. Looks like an indented list. Easier to read than JSON.
- **Markdown:** a simple way to write formatted text using plain characters. Pound sign for headings, asterisks for bold.

## 3. Setting Up GitHub From Your Computer

Your GitHub account already exists. The work below is teaching git on your computer how to talk to it.

### 3.1 Tell Git Who You Are

Open your terminal. Type these two commands, swapping in your real name and the email tied to your GitHub account.

```
git config --global user.name "Your Name"
git config --global user.email "your@email.com"
```

This is one time. Git remembers it forever on this computer.

### 3.2 Connect to GitHub Using a Personal Access Token

HTTPS with a Personal Access Token is the simplest path. SSH keys also work fine if you prefer them.

1. In a browser, sign in to GitHub. Click your profile picture top right, then Settings.
2. On the left, scroll down and click Developer settings.
3. Click Personal access tokens, then Tokens (classic), then Generate new token (classic).
4. Note: type a description like "Course building computer."
5. Expiration: 90 days is fine. You can regenerate when it expires.
6. Scopes: check the box for repo. That is all you need for private repo push and pull.
7. Click Generate token. Copy the token. You will only see it once. Save it somewhere safe (1Password or similar).

Tell git to remember the token so you do not have to paste it on every push.

```
git config --global credential.helper store
```

First time you push, git will ask for your username and password. Username is your GitHub username. Password is the token you just copied. After that, git stores it and stops asking.

### 3.3 Create the Repo on GitHub

1. Go to github.com and sign in.
2. Click the green New button or the plus sign in the top right and choose New repository.
3. Repository name: {COURSE_SLUG}
4. Description: {COURSE_NAME} course content and {TARGET_PLATFORM} sync
5. Privacy: choose Private. Course content is your IP.
6. Check the box for Add a README file.
7. Skip the .gitignore and license dropdowns for now. We add those later.
8. Click Create repository.

You now have an empty repo on GitHub with one file in it (the README).

### 3.4 Clone the Repo to Your Computer

In your terminal, decide where you want repos to live. A Code folder in your home directory works.

```
mkdir -p ~/Code
cd ~/Code
```

Now clone the repo. Replace the username in the URL with your actual GitHub username.

```
git clone https://YOUR-USERNAME@github.com/YOUR-USERNAME/{COURSE_SLUG}.git
cd {COURSE_SLUG}
```

Important: anywhere this doc shows YOUR-USERNAME or YOUR-API-KEY in all caps, swap in the real value before running.

Private repo gotcha: if your repo is private, git will not even prompt for credentials when given a bare URL. It will fail with "repository not found" because GitHub will not confirm a private repo exists to anonymous callers. The username embedded URL format above forces git to ask for the password.

### 3.5 Pasting Tokens at Password Prompts

When git asks for a password, it wants the token, not a real password.

- Copy the token from your password manager. Make sure you only grab the `ghp_` string itself, not any prefix or label.
- Click into the terminal.
- Paste with Ctrl plus Shift plus V. Regular Ctrl plus V does not work in Linux terminals.
- The screen will look like nothing happened. The terminal hides password input on purpose.
- Press Enter once.

If you get an error like "credential value for password contains carriage return," the copy picked up an invisible newline character. Re highlight just the token text in your password manager, right click, Copy, and try again.

## 6. Repo Structure

```
{COURSE_SLUG}/
  README.md

  course-config.yaml
  course-description.md
  voice-guide.md
  content/

      knowledge-check.yaml
    unit-02-{second-unit-slug}/
    [...continues through unit {UNIT_COUNT}...]
  exam/
    course-final.yaml
  scripts/
    sync.py
    validate.py
    helpers/
  docs/
    build-spec.md
```

What each folder is for:

- **content/** holds the course material. One folder per unit.
- **exam/** holds the course final assessment. The comprehensive end of course test.
- **scripts/** holds the Python files that read your content and push it to {TARGET_PLATFORM}.
- **course-config.yaml** at the top defines course settings (name, price, completion threshold).
- **course-description.md** at the top is the course description (audience, outcomes, scope).
- **voice-guide.md** at the top defines the voice for this specific course. The lesson-drafter skill reads it.
- **.env.example** is a template for the secret API key file. The real .env file you create later and never commit.
- **.gitignore** tells git which files to skip.

## 8. What the Sync Script Does

scripts/sync.py is the worker. When you run it, it does this:

- Loads your secret API key from the .env file.
- Reads course-config.yaml. Creates the course on {TARGET_PLATFORM} if it does not exist. Updates it if it does.
- Walks the content folder one unit at a time. Creates the chapter, pushes each lesson, creates the unit quiz.
- Reads the course final question bank. Creates or updates the final assessment quiz.
- Logs a summary at the end.

The script is idempotent. Safe to run a hundred times in a row. Each run just makes {TARGET_PLATFORM} match what is in your files. No duplicates.

scripts/validate.py runs first as a safety check. Catches typos, missing fields, duplicate IDs, questions with no correct answer marked. Run it before every sync.
